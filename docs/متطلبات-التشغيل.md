# متطلبات تشغيل نظام Sufra Lite POS

> **الإصدار:** 0.1.17  
> **المنتج:** Sufra Lite POS — نظام نقاط بيع للمطاعم  
> **المطوّر:** Aman Technology

---

## 1. نظرة عامة

Sufra Lite POS تطبيق سطح مكتب (Electron) يعمل على **Windows** ويُشغّل خادم API محليًا على الشبكة الداخلية (LAN). يدعم النظام:

- **وضع الخادم (Host):** جهاز حاسوب رئيسي يشغّل التطبيق ويستضيف قاعدة البيانات والـ API.
- **وضع العميل (Client):** أجهزة لوحية أو هواتف أو حواسيب أخرى تتصل بخادم LAN عبر المتصفح أو تطبيق PWA/Android.

## 3. متطلبات البرمجيات

### 3.1 للتشغيل (نسخة مثبتة — Production)

| المتطلب | التفاصيل |
|---------|----------|
| **نظام التشغيل** | Windows 10/11 (64-bit) فقط |
| **Node.js** | **غير مطلوب** — مُضمّن داخل المثبّت |
| **صلاحيات التثبيت** | تثبيت على مستوى الجهاز (perMachine) — يتطلب صلاحيات مدير |
| **مثيل واحد** | يُسمح بمثيل واحد فقط من التطبيق في وقت واحد (Single Instance) |
| **اتصال إنترنت** | اختياري — مطلوب للتحديثات التلقائية والترخيص عبر المنصة فقط |

### 3.2 للتطوير (Development)

| المتطلب | الإصدار |
|---------|---------|
| **Node.js** | 20.x أو أحدث (متوافق مع Electron 30) |
| **npm** | 9.x أو أحدث |
| **Git** | أي إصدار حديث |
| **أدوات بناء Windows** | Visual Studio Build Tools (لـ `better-sqlite3`, `bcrypt`, `canvas`) |

#### الإعداد لأول مرة

```bash
# من جذر المشروع — يثبت كل التبعيات ويجهّز better-sqlite3
npm run setup

# ثم (مرة واحدة) بعد تثبيت Visual Studio Build Tools:
npm run rebuild:native --prefix electron

# تشغيل التطوير
npm run dev
```

> **ملاحظة:** إذا ظهر `'npm-run-all' is not recognized` فهذا يعني أنك لم تشغّل `npm install` في جذر المشروع بعد.

#### أوامر التشغيل

```bash
# من جذر المشروع — تشغيل الواجهة والـ Electron معًا
npm run dev

# أو بشكل منفصل:
npm run dev:frontend   # Vite على المنفذ 3000
npm run dev:electron   # Electron + Fastify API على المنفذ 3333
```

#### بناء المثبّت (Windows)

```bash
npm run dist
# أو من مجلد electron:
cd electron && npm run dist
```

## 4. متطلبات الشبكة

### 4.1 المنافذ (Ports)

| المنفذ | البروتوكول | الاستخدام | ملاحظات |
|--------|-----------|-----------|---------|
| **3333** | HTTP + WebSocket (Socket.IO) | API الرئيسي + الواجهة (Production) + الأحداث الفورية | يستمع على `0.0.0.0` — متاح لكل أجهزة LAN |
| **3000** | HTTP | Vite dev server | **التطوير فقط** — غير مطلوب في الإنتاج |
| **9100** | TCP | طابعات حرارية شبكية (ESC/POS) | منفذ الطابعة الافتراضي |
| **3850** | HTTP/HTTPS | خادم الترخيص (License Platform) | اختياري — للتحقق من الترخيص عبر المنصة |

### 4.2 متطلبات الشبكة الداخلية (LAN)

- يجب أن تكون جميع الأجهزة (الخادم والعملاء) على **نفس الشبكة المحلية**.
- عناوين IP المدعومة للعملاء: `192.168.x.x`, `10.x.x.x`, `172.16–31.x.x`.
- يُفضّل فتح المنفذ **3333** في جدار الحماية (Windows Firewall) للسماح بالاتصال من الأجهزة الأخرى.
- **لا يُدعم** الاتصال عبر الإنترنت العام (Public IP) — النظام مصمم للعمل داخل LAN فقط.

### 4.3 Socket.IO (الأحداث الفورية)

- يعمل على نفس منفذ **3333**.
- يُستخدم لمزامنة الطلبات والإشعارات بين الأجهزة في الوقت الفعلي.
- يتوقف تلقائيًا عند إغلاق تطبيق Electron.

## 5. الترخيص (License)

### 5.1 نظام الترخيص

النظام يستخدم **ترخيصًا مربوطًا بالجهاز (Machine-Bound)** مع توقيع رقمي.

| البند | التفاصيل |
|-------|----------|
| **معرّف الجهاز (Machine ID)** | يُستخرج عبر أداة `machine-id-tool/Get-Machine-ID.bat` |
| **أنواع الترخيص** | `5d` (5 أيام), `15d`, `1m` (شهر), `2m`, `1y` (سنة), `lifetime` (مدى الحياة) |
| **ملف الترخيص** | ملف JSON موقّع رقميًا — يُستورد من داخل التطبيق |
| **التحقق** | محلي (offline) + مزامنة دورية مع خادم المنصة (اختياري) |

### 5.2 خطوات التفعيل للعميل

1. تشغيل `Get-Machine-ID.bat` وإرسال Machine ID للبائع.
2. استلام مثبّت مخصّص أو ملف ترخيص.
3. فتح التطبيق → صفحة التفعيل → استيراد ملف الترخيص.

### 5.3 خادم المنصة (License Platform)

| المتغير | الوصف |
|---------|-------|
| `AMAAN_PLATFORM_URL` | عنوان خادم الترخيص (مثال: `http://127.0.0.1:3850`) |
| ملف `platform-license-url.txt` | يُحفظ في مجلد بيانات التطبيق كبديل للمتغير |

## 6. الطابعات

### 6.1 الطابعات الحرارية (Thermal Printers)

| المتطلب | التفاصيل |
|---------|----------|
| **النوع** | طابعة حرارية ESC/POS |
| **العرض** | 80mm (576 بكسل) |
| **الاتصال** | شبكة LAN (TCP/IP) — المنفذ **9100** |
| **الاستخدام** | طباعة إيصالات المطبخ وإيصالات العملاء |

### 6.2 إعداد الطابعات

- تُكوَّن من **الإعدادات → الطابعات** داخل التطبيق.
- لكل مطبخ (Kitchen) يمكن تعيين طابعة شبكية بعنوان IP ومنفذ.
- يدعم النظام اكتشاف الطابعات تلقائيًا عبر مسح الشبكة المحلية (port 9100).

### 6.3 طابعات USB (Windows)

- يدعم النظام `@thiagoelg/node-printer` لاكتشاف طابعات USB المتصلة بالحاسوب.
- تظهر حالة الطابعة في **لوحة التحكم → حالة النظام**.

## 7. قاعدة البيانات والتخزين

### 7.1 قاعدة البيانات

| البند | التفاصيل |
|-------|----------|
| **المحرك** | SQLite (better-sqlite3) |
| **الوضع** | WAL (Write-Ahead Logging) |
| **الموقع (Production)** | `%APPDATA%\Sufra Lite POS\sufra.sqlite` |
| **الموقع (Development)** | `electron/backend/data/sufra.sqlite` |

### 7.2 مجلدات البيانات

| المجلد | المحتوى |
|--------|---------|
| `uploads/` | صور الأصناف والملفات المرفوعة (حد أقصى 5 MB لكل ملف) |
| `uploads/items/` | صور الأصناف |
| `reports-history/` | سجل التقارير المحفوظ |
| `logs/` | سجلات التشغيل |
| `recipe-print-branding.json` | إعدادات طباعة الوصفات |

### 7.3 متطلبات القرص

- **500 MB** كحد أدنى لمساحة البيانات (تنمو مع الصور والتقارير).
- يُنصح بعمل **نسخ احتياطي دوري** لملف `sufra.sqlite` ومجلد `uploads/`.

## 10. استكشاف الأخطاء الشائعة

| المشكلة | السبب المحتمل | الحل |
|---------|--------------|------|
| **المنفذ 3333 مستخدم** | مثيل آخر من التطبيق يعمل | `taskkill /F /IM electron.exe` ثم إعادة التشغيل |
| **تعذّر الاتصال من الجهاز اللوحي** | جدار الحماية أو شبكة مختلفة | التأكد من نفس LAN + فتح المنفذ 3333 |
| **الطابعة لا تطبع** | IP خاطئ أو المنفذ 9100 مغلق | التحقق من IP الطابعة وإعدادات الشبكة |
| **الترخيص مرفوض** | Machine ID مختلف أو انتهت الصلاحية | إعادة إرسال Machine ID للبائع |
| **قاعدة البيانات تالفة** | انقطاع كهربائي أثناء الكتابة | استعادة من نسخة احتياطية لـ `sufra.sqlite` |
| **Vite dev server غير متاح** | الواجهة لم تُشغَّل | `npm run dev:frontend` في terminal منفصل |
